# System Boundaries & Interfaces — Camp CRM

**Version:** 1.0 · **Generated:** 2026-09-11

This document covers everything crossing the system's boundary: the HTTP API its own UI consumes, the pages a browser can reach, the ops commands operators run, the environment configuration the code reads, and the filesystem contract for documents. A recurring theme: the public surface is exactly as large as the enrollment form requires — and not one endpoint larger.

---

## 1. HTTP API

Camp CRM has no public "developer API" — the routes under `/api/*` are the UI's own write path. There is no versioning, no CORS configuration and no rate limiting; treat them as internal interfaces.

### 1.1 Public endpoints (no session required)

These four endpoints are what makes a no-account enrollment possible; each one carries its own guard (validation, capability token, or deliberate read-only minimality).

| Method | Path | Purpose | Request | Response / Errors |
|---|---|---|---|---|
| GET | `/api/eventi` | Active events for the enrollment form | — | 200 JSON array of active events (name, year, dates, location, 5 price fields, `rules`, `participantLimit`) · `src/app/api/eventi/route.ts` L7 |
| GET | `/api/eventi/[id]/posti` | Seat availability | — | 200 `{ limit, taken, remaining }` (`remaining: null` = unlimited); 404 unknown event · `src/app/api/eventi/[id]/posti/route.ts` L7 |
| POST | `/api/registrazioni` | Create enrollment | JSON: `eventId`, `sottoscritto*` name/phone/email, `street`/`postalCode`/`city`, `notes`, `participants[{role, firstName, lastName, birthDate, taxId?, notes?}]`, `privacyConsent`, `rulesConsent` | 201 registration incl. participants **+ one-time `uploadToken`**; 400 validation / missing consent; 404 unknown event; 409 capacity exceeded · `src/app/api/registrazioni/route.ts` L36 |
| POST | `/api/partecipanti/[id]/documento` | Upload/replace an ID document | `multipart/form-data` field `file`; header `X-Upload-Token` equal to the registration's token (compared constant-time) | 201 document metadata; 400 invalid multipart or file; 403 bad token; 404 unknown participant · `src/app/api/partecipanti/[id]/documento/route.ts` L88 |

Example — enroll and upload:

```bash
# 1. Create the enrollment (public)
curl -X POST https://host/api/registrazioni -H 'Content-Type: application/json' -d '{
  "eventId": "clx…", "sottoscrittoFirstName": "Anna", "sottoscrittoLastName": "Rossi",
  "participants": [{"role":"KID","firstName":"Luca","lastName":"Rossi","birthDate":"01/02/2015"}],
  "privacyConsent": true, "rulesConsent": true }'
# → 201 { ..., "uploadToken": "<64 hex chars>" }

# 2. Upload the camper's document with the capability token (public)
curl -X POST https://host/api/partecipanti/<participantId>/documento \
  -H "X-Upload-Token: <token>" -F "file=@id-card.pdf"
```

## 3. CLI / operations interface

| Command | Mode | Behavior | Source |
|---|---|---|---|
| `npm run retention:purge` | dry-run (default) | Lists registrations whose event ended > `RETENTION_MONTHS` ago, with participant and document counts; deletes nothing; idempotent | `scripts/purge-expired-registrations.ts` |
| `npm run retention:purge -- --execute` | execute | Irreversibly purges those registrations incl. encrypted files; non-zero exit on failures. Cron example: `docker compose exec -T camp-crm npm run retention:purge -- --execute` | same |
| `npm run encrypt:migrate` | one-off | Encrypts legacy plaintext documents; skips `CCLE`-magic files; per-file atomic (tmp + rename); validates key before touching anything | `scripts/migrate-encrypt-documents.ts` |
| `npm run db:seed` | seed | Upserts ADMIN/STAFF users from `SEED_*` env (defaults `admin@camp.it`/`staff@camp.it`); never overwrites existing users | `prisma/seed.ts` |
| `npm run db:migrate` / `npm run db:studio` | dev | `prisma migrate dev` / Prisma Studio | `package.json` |
| container entrypoint | boot | `prisma migrate deploy` → seed → `node server.js` | `docker-entrypoint.sh` |

## 4. Configuration (environment variables)

These variables are the system's only configuration surface — there is no config file beyond `next.config.ts` build settings. Each exists because some fact (a secret, a legal identity, a retention period) must be environment-specific.

| Variable | Type / format | Default | Meaning & effect |
|---|---|---|---|
| `DATABASE_URL` | SQLite URL | `file:./dev.db` (dev) / `file:./data/dev.db` (container) | Where the single database file lives — move it, move the whole database |
| `AUTH_SECRET` | random string | — (required in production) | Signs Auth.js JWTs; rotating it invalidates all sessions |
| `AUTH_URL` | URL | — | Canonical origin for Auth.js in deployment |
| `DOCUMENT_ENCRYPTION_KEY` | base64 of exactly 32 bytes (`openssl rand -base64 32`) | — | AES-256-GCM key for documents. **Missing/invalid ⇒ uploads fail closed** (throw), never plaintext. Loss ⇒ all documents unrecoverable |
| `UPLOADS_DIR` | filesystem path | `./data/uploads` | Root of the document store; bind-mount target for external disks (`docker-compose.yml` recipe) |
| `RETENTION_MONTHS` | positive integer | 24 | Months after `event.endDate` before a registration becomes purge-eligible; also rendered in `/privacy` |
| `DATA_CONTROLLER_NAME` | string | placeholder text | Legal controller identity shown in `/privacy`; must be set before production or the notice is non-compliant |
| `DATA_CONTROLLER_EMAIL` | email | placeholder text | Contact for data-subject rights requests, shown twice in `/privacy` |
| `SEED_ADMIN_EMAIL` / `_NAME` / `_PASSWORD` | strings | `admin@camp.it` / `Amministratore` / `admin123` | First-boot ADMIN account — used only if the user doesn't already exist |
| `SEED_STAFF_EMAIL` / `_NAME` / `_PASSWORD` | strings | `staff@camp.it` / `Operatore` / `staff123` | First-boot STAFF account — same rules |

## 5. Filesystem contract

```
UPLOADS_DIR/                                  # default ./data/uploads, env-overridable
└── participants/
    └── <participantId>/                      # one folder per participant (cuid)
        └── <uuid>.<pdf|jpg|png|webp>         # AES-256-GCM envelope ("CCLE" magic), server-named
```

Rules enforced in code: filenames are generated UUIDs (client names become display metadata only); `documentAbsolutePath` rejects `/`, `\`, `..` (`src/lib/uploads.ts` L121); extension comes from the server-observed mime (L47-56). Outside this tree the system touches no other paths (SQLite path comes from `DATABASE_URL`).

## 6. Integration notes

- **Deploying**: set `AUTH_SECRET` + `DOCUMENT_ENCRYPTION_KEY` + controller variables, `docker compose up -d`, then run `encrypt:migrate` once if any pre-encryption documents exist; schedule the retention cron. Backups: database volume + uploads directory + the key, deliberately stored apart.
- **Programmatic enrollment**: `POST /api/registrazioni` + token-based document upload is a complete, scriptable intake flow — but remember it is unversioned and unauthenticated by design; put a proxy with rate limiting in front if you expose it beyond the origin.
- **Not integration points (yet)**: no webhooks, no email, no payment gateway callbacks — anything eventful (new enrollment, payment recorded) must currently be observed by polling the authenticated GET endpoints.
